## Goal

Populate `match_id` from symbol resolution and ensure all `SpanResult` instances have unique `span_id` values. This enables tracking which symbols were resolved and linking spans back to their resolution events.

### Task 1: Modify resolve_symbol to generate match_id

**File:** `src/resolve/mod.rs`

**Current Function Signature (lines 71-165):**
```rust
pub fn resolve_symbol(
    graph: &CodeGraph,
    file: Option<&Path>,
    kind: Option<&str>,
    name: &str,
) -> Result<ResolvedSpan>
```

**Issue:** `ResolvedSpan` has a `node_id: NodeId` field that's internal to SQLiteGraph and not serializable. We need to add a `match_id` that can be serialized.

**Option A:** Add `match_id` field to `ResolvedSpan` struct
- Pro: Keeps match_id with the span
- Con: Modifies existing struct used by consumers

**Option B:** Change return type to tuple `(ResolvedSpan, String)`
- Pro: Doesn't break existing ResolvedSpan struct
- Con: More awkward to use

**Decision:** Option A - Add `match_id` to `ResolvedSpan`

**Changes:**

1. Add `match_id` field to `ResolvedSpan` (after `node_id`):
```rust

```

**Issue:** The `From` impl generates a new `span_id` and doesn't copy `match_id` from `ResolvedSpan`.

**Changes:**
```rust
impl From<crate::resolve::ResolvedSpan> for SpanResult {
    fn from(span: crate::resolve::ResolvedSpan) -> Self {
        use uuid::Uuid;
        Self {
            file_path: span.file_path,
            symbol: Some(span.name),
            kind: Some(span.kind),
            byte_start: span.byte_start,
            byte_end: span.byte_end,
            line_start: span.line_start,
            line_end: span.line_end,
            col_start: span.col_start,
            col_end: span.col_end,

            match_id: Some(span.match_id),  // <-- COPY match_id from ResolvedSpan
            before_hash: None,
            after_hash: None,
        }
    }
}
```

**Note:** We still generate a fresh `span_id` because `ResolvedSpan` doesn't have one. The `match_id` is copied to link the span back to its resolution.

### Task 4: Update delete command to handle match_id for references

**File:** `src/main.rs`

**Current Code (lines 239-243):**
```rust
// Step 6: Find all references to the symbol
// Note: Reference finding is still Rust-only (Phase 4 will add multi-language)
let ref_set = find_references(&code_graph, file_path, symbol_name, None)?;
```

**Issue:** `find_references()` returns `ReferenceSet` which contains `Reference` structs. These don't have `match_id` because they come from graph queries, not `resolve_symbol()`.

**Analysis:**
- The definition span can use `match_id` from `resolve_symbol()`
- Reference spans come from `find_references()` which doesn't call `resolve_symbol()` for each reference

**Decision:** For Phase 4, reference spans will have `match_id: None`. The definition span will have a `match_id`. Future phases can add `match_id` to references if needed.

**Changes:**
1. For the definition span: use `resolve_symbol()` result which has `match_id`
2. For reference spans: generate `SpanResult` with `match_id: None`

**Implementation:**
```rust
// In delete command JSON output section

// Resolve the definition to get match_id
let resolved_def = resolve_symbol(&code_graph, Some(file_path), kind_str, symbol_name)?;
let def_match_id = resolved_def.match_id.clone();

// Create span result for definition with match_id
let def_span_result: SpanResult = resolved_def.clone().into();

// Create span results for references (no match_id)
let mut spans: Vec<SpanResult> = Vec::new();
spans.push(def_span_result);  // Has match_id

for r in &ref_set.references {
    spans.push(SpanResult::from_byte_span(
        r.file_path.clone(),
        r.byte_start,
        r.byte_end,
    ));  // match_id is None
}
```

### Task 6: Verify span_id uniqueness

**Goal:** Ensure each `SpanResult` gets a unique `span_id` even when created from the same source.

**Test Cases:**
1. Two `SpanResult::from_byte_span()` calls with same args → different `span_id`
2. Two `From<ResolvedSpan>` calls with same `ResolvedSpan` → different `span_id`
3. `SpanResult` created via `with_match_id()` preserves `match_id` but generates new `span_id`

**Implementation:** Add unit tests to `src/output.rs`:
```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_span_id_uniqueness() {
        let span1 = SpanResult::from_byte_span("test.rs".to_string(), 10, 20);
        let span2 = SpanResult::from_byte_span("test.rs".to_string(), 10, 20);
        assert_ne!(span1.span_id, span2.span_id);
    }

    #[test]
    fn test_match_id_preserved() {
        let match_id = uuid::Uuid::new_v4().to_string();
        let span = SpanResult::from_byte_span("test.rs".to_string(), 10, 20)
            .with_match_id(match_id.clone());
        assert_eq!(span.match_id, Some(match_id));
    }
}
```
