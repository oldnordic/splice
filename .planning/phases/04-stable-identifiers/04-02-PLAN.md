# Plan 04-02: execution_id Integration

**Status:** 📋 PLANNED
**Depends on:** 04-01 (ID Generation Utilities)
**Research:** Complete (analyzed main.rs usage patterns)

---

## Goal

Ensure `operation_id` (also called `execution_id` in some contexts) is consistently propagated from CLI flags through to the final structured output. Currently, the CLI accepts `--operation-id` but generates a new UUID instead of using the provided value.

## Tasks

### Task 1: Update patch command to propagate operation_id

**File:** `src/main.rs`

**Current Code (lines 629-673):**
```rust
// Check if JSON output is requested
if _json_output {
    use splice::output::{OperationResult, OperationData, PatchResult, SpanResult};
    use uuid::Uuid;

    // Create span result
    let span = SpanResult::from_byte_span(...)
        .with_symbol(symbol_name.to_string(), resolved.kind.to_string())
        .with_hashes(summary.before_hash.clone(), summary.after_hash.clone());

    // Create patch result
    let patch_result = PatchResult {
        file: file_path.to_string_lossy().to_string(),
        symbol: symbol_name.to_string(),
        kind: resolved.kind.to_string(),
        spans: vec![span],
        before_hash: summary.before_hash.clone(),
        after_hash: summary.after_hash.clone(),
        lines_added: 0,
        lines_removed: 0,
    };

    // Create operation result
    let _op_id = operation_id.clone().unwrap_or_else(|| Uuid::new_v4().to_string());
    let result = OperationResult::new("patch".to_string())  // <-- BUG: generates NEW UUID
        .success(format!(
            "Patched '{}' at bytes {}..{} (hash: {} -> {})",
            ...
        ))
        .with_workspace(workspace_root.to_string_lossy().to_string())
        .with_result(OperationData::Patch(patch_result));
```

**Issue:** `_op_id` is computed but never used - `OperationResult::new()` generates a fresh UUID.

**Changes:**
1. Change `OperationResult::new()` to `OperationResult::with_id(..., operation_id.clone())`
2. Remove the unused `_op_id` variable

**Expected Result:**
```rust
if _json_output {

    let patch_result = PatchResult { ... };

    // Use operation_id from CLI or generate new UUID

    )
    .success(format!(
        "Patched '{}' at bytes {}..{} (hash: {} -> {})",
```

### Task 5: Update error payloads to include operation_id

**File:** `src/main.rs`

**Current Code (lines 98-120):**
```rust
match result {
    Ok(payload) => match emit_success_payload(&payload, json_output) {
        Ok(()) => ExitCode::SUCCESS,
        Err(err) => {
            if matches!(err, splice::SpliceError::BrokenPipe) {
                ExitCode::SUCCESS
            } else {
                let payload = splice::cli::CliErrorPayload::from_error(&err);
                emit_error_payload(&payload, json_output);
                ExitCode::from(1)
            }
        }
    },
    Err(e) => {
        if matches!(e, splice::SpliceError::BrokenPipe) {
            ExitCode::SUCCESS
        } else {
            let payload = splice::cli::CliErrorPayload::from_error(&e);
            emit_error_payload(&payload, json_output);
            ExitCode::from(1)
        }
    }
}
```

**Observation:** When errors occur, the `operation_id` may have been provided by the user but the error payload doesn't include it. Consider how to handle this.

**Decision:** For Phase 4, we'll leave error handling as-is. The error payload already includes sufficient information. Including `operation_id` in error payloads can be deferred to a future phase.
