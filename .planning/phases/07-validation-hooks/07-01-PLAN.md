# Plan 07-01: Design Checksum System

**Phase:** 7 - Validation Hooks
**Status:** PENDING
**Dependencies:** None (Phase 5 complete - metadata enables checksums)
**Estimated Complexity:** Medium

## Objective

Design and implement a comprehensive checksum system for tracking file integrity before, during, and after refactoring operations. The checksum system will enable pre-verification hooks that validate file state before any modifications and post-verification hooks that verify successful changes.

## Context

**Current State:**
- `compute_hash()` already exists in `src/patch/mod.rs:577` and `src/patch/backup.rs:252`
- SHA-256 hashing is already used for file integrity in backup system
- `PatchResult` and `FilePatchSummary` already include `before_hash` and `after_hash` fields
- `SpanResult` has optional `before_hash`/`after_hash` fields (currently unused in most contexts)

**Gap Analysis:**
1. No pre-operation checksum verification (files may be modified externally between operations)
2. No span-level checksums (only file-level)
3. No checksum persistence for audit trail
4. No checksum-based change detection (is file actually different?)
5. No checksum verification in batch operations (apply_files, plan multi-step)

## Research Required

**Checksum Algorithms:**
- SHA-256 is current choice (via `sha2` crate)
- Consider: BLAKE3 for faster hashing (benchmarks show 3-10x faster)
- Consider: xxHash for extremely fast non-cryptographic hashing

**Relevant Patterns:**
- Rust's `cargo` uses SHA-256 for Cargo.lock
- `git` uses SHA-1 (deprecated) for objects
- Compiler build systems often use timestamp + size as fast check, then hash

**Questions to Answer:**
1. Should we support multiple checksum algorithms? (SHA-256 required for compatibility, BLAKE3 optional)
2. Should checksums be stored in a persistent database for audit trails?
3. How do we handle binary files vs text files?

## Implementation Plan

### Step 1: Create Checksum Module

**File:** `src/checksum.rs` (new)

```rust
//! File and span checksum computation for validation hooks.
//!
//! Provides deterministic checksums for:
//! - Entire files (SHA-256 for compatibility)
//! - Byte spans within files (for verification)
//! - Line ranges (for pre/post validation)

use sha2::{Digest, Sha256};
use std::path::Path;

/// Checksum algorithm types.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ChecksumAlgorithm {
    /// SHA-256 (default, cryptographically secure)
    Sha256,
    /// BLAKE3 (optional, faster, future-proof)
    #[cfg(feature = "blake3")]
    Blake3,
}

/// Computed checksum with metadata.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Checksum {
    /// Hex-encoded checksum value
    pub value: String,
    /// Algorithm used
    pub algorithm: ChecksumAlgorithm,
    /// Byte count of checksummed content
    pub size: usize,
}

/// Compute checksum of entire file.
pub fn checksum_file(path: &Path) -> Result<Checksum>;

/// Compute checksum of byte span within file.
pub fn checksum_span(path: &Path, start: usize, end: usize) -> Result<Checksum>;

/// Compute checksum of line range within file.
pub fn checksum_line_range(path: &Path, line_start: usize, line_end: usize) -> Result<Checksum>;

/// Verify file matches expected checksum.
pub fn verify_file(path: &Path, expected: &Checksum) -> Result<bool>;
```
