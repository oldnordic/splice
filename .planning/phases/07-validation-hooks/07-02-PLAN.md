# Plan 07-02: Implement Pre-Verification Hooks

**Phase:** 7 - Validation Hooks
**Status:** PENDING
**Dependencies:** 07-01 (checksum system required)
**Estimated Complexity:** Medium

## Objective

Implement pre-verification hooks that validate file state and workspace conditions before applying any refactoring operations. Pre-verification prevents accidental corruption, detects external modifications, and ensures safe operating conditions.

## Context

**Current State:**
- `apply_patch_with_validation()` computes before_hash but only uses it for output
- No validation of file state before patching (assumes file hasn't changed)
- `validate_replacements()` in `src/patch/mod.rs` validates span bounds but not file integrity
- Backup system creates backups AFTER reading file (too late if file was already corrupted)

**Gap Analysis:**
1. No pre-check for external file modifications (race condition)
2. No verification that workspace is in valid state (e.g., cargo build passes)
3. No check for unsaved changes in editors
4. No verification that graph database is in sync with files
5. No pre-check for file permissions (write access)

## Research Required

**Pre-Validation Patterns:**
- Database transactions: BEGIN, validate, COMMIT/ROLLBACK
- Package managers: `npm ci` validates lock file before install
- Build systems: timestamp checks before recompilation
- Git: `pre-commit` hooks run before commit

**Failure Modes:**
1. File modified between graph indexing and patch operation
2. Workspace has uncommitted changes (user should be warned)
3. Disk full (cannot complete rollback even if validation passes)
4. File is read-only (patch will fail)
5. Graph database out of sync (stale cache)

## Implementation Plan

### Step 1: Create Pre-Verification Module

**File:** `src/verify.rs` (new)

```rust
//! Pre-verification hooks for safe refactoring operations.
//!
//! Pre-verification runs BEFORE any file modifications to:
//! - Validate file state (unchanged, writable, readable)
//! - Verify workspace conditions (disk space, permissions)
//! - Check graph database synchronization
//! - Detect external modifications (via checksums)

use crate::checksum::{Checksum, checksum_file};
use crate::error::{Result, SpliceError};
use std::path::Path;

/// Pre-verification result.
#[derive(Debug, Clone, PartialEq)]
pub enum PreVerificationResult {
    /// All checks passed, safe to proceed.
    Pass,

    /// Check failed with details.
    Fail {
        /// Check that failed
        check: String,
        /// Failure reason
        reason: String,
        /// Whether this is a blocking failure (true) or warning (false)
        blocking: bool,
    },
}

/// Verify file is ready for patching operation.
///
/// Checks:
/// - File exists and is readable
/// - File is writable (can be modified)
/// - File checksum matches expected (no external modification)
/// - File is within workspace bounds
pub fn verify_file_ready(
    file_path: &Path,
    expected_checksum: Option<&Checksum>,
    workspace_root: &Path,
) -> PreVerificationResult;

/// Verify workspace has sufficient resources.
///
/// Checks:
/// - Disk space available (estimate 2x file size for safety)
/// - Write permissions in workspace
/// - Backup directory can be created
pub fn verify_workspace_resources(
    workspace_root: &Path,
    estimated_size: usize,
) -> PreVerificationResult;

/// Verify graph database is in sync with files.
///
/// Checks:
/// - Database file exists and is readable
/// - File modification time <= database last update time
pub fn verify_graph_sync(
    file_path: &Path,
    db_path: &Path,
) -> PreVerificationResult;

/// Run all pre-verification checks for a patch operation.
pub fn pre_verify_patch(
    file_path: &Path,
    expected_checksum: Option<&Checksum>,
    workspace_root: &Path,
    db_path: &Path,
) -> Result<Vec<PreVerificationResult>>;
```

    workspace_root: &Path,
    replacements: BTreeMap<PathBuf, Vec<SpanReplacement>>,
    language: SymbolLanguage,

    let mut results = Vec::new();
