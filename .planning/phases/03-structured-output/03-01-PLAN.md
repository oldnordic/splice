**From DISCOVERY.md:**
The codebase has mixed JSON output patterns:
- Well-structured: Plan (Plan, PatchStep), CLI payloads (CliSuccessPayload, CliErrorPayload, DiagnosticPayload)
- Partially structured: Patch (PreviewReport has Serialize, FilePatchSummary missing Serialize)
- Not serializable: Resolve (ResolvedSpan has no Serialize, line/col are placeholder 0 values)
- Ad-hoc: Uses serde_json::Value in CLI success payload

**Key Design Decisions:**
1. Explicit fields over ad-hoc JSON - avoid Value where possible
2. Consistent snake_case field names with serde rename for CLI compatibility
3. Version field on all top-level structs
4. Unified span representation (byte_start, byte_end, line_start, line_end, col_start, col_end)

**Files to reference:**
- src/plan/mod.rs: Plan, PatchStep structs
- src/patch/mod.rs: PreviewReport, FilePatchSummary structs
- src/resolve/mod.rs: ResolvedSpan struct
- src/cli/mod.rs: CliSuccessPayload, CliErrorPayload, DiagnosticPayload structs
