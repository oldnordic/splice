**Current State (SQLiteGraph 0.2.11):**
- Uses `sqlitegraph::{EdgeSpec, GraphBackend, NodeId, NodeSpec}`
- Uses `sqlitegraph::{Label, PropertyKey}` for schema definitions
- Uses `GraphConfig::sqlite()` for configuration
- Uses `sqlitegraph::open_graph(path, &cfg)` for opening graph
- Error type: `sqlitegraph::SqliteGraphError` (via `#[from]`)

**Target State (SQLiteGraph 1.0):**
Per docs/manual.md and docs/API.md:
- **Dual backend architecture**: SQLite backend and Native V2 backend
- **Native V2 API**: `GraphConfig::native()`, `open_graph(path, &config)`
- **SQLite backend API**: `SqliteGraph::open()`, `GraphEntity` instead of `NodeSpec`
- **Feature flags**: `native-v2` feature required for Native V2 backend
- **Same types**: `NodeSpec`, `EdgeSpec`, `NodeId` still exist in Native V2 API
- **Label/PropertyKey**: Still used in schema module

**Key Migration Decisions Needed:**
1. Which backend to use? (Roadmap says "Native V2 backend")
2. How to handle existing databases?
3. Are there breaking changes in the types we use?

**Files Using SQLiteGraph:**
- src/graph/mod.rs (284 lines) - Main integration layer
- src/graph/schema.rs (131 lines) - Label/PropertyKey definitions
- src/error.rs (line 28) - Error type integration
- src/resolve/mod.rs (line 13) - NodeId type usage
